# Космос как инфраструктура — запуск и воспроизведение

Локальный аналитический инструмент для синтетического кейса v1.1: четыре лота, режимы A/B/C, девять ограничений, BASE/STRESS, ручное сравнение и полный перебор с явно заданными весами. Числа считает Python на сохранённом исходном ядре. VPUB не является CASH; KCASH — отношение сумм CASH/OPEX, не прибыльность.

## Комплект

В готовом GitVerse-комплекте этот файл называется README.md. Исходный README организаторов сохранён без изменений в case_source/README.md. `KIT_MANIFEST.json` содержит точный список поставляемых файлов и SHA-256. Здесь нет конфиденциального jury-notebook, исходных ZIP, полных статей организаторов, ключей, окружений или сырых агентных логов. Исторический путь archive_path в неизменном config/source_manifest.json служит только метаданными происхождения: приложение его не открывает, архив не требуется.

Для Windows выберите короткую папку, например C:/kosmos. Не помещайте комплект в глубоко вложенный путь. Не запускайте notebook/bootstrap и не импортируйте новые источники из сети.

## Локальный запуск без Docker

Нужны Python 3.12 и, только для пересборки интерфейса, Node 22/npm. Все команды выполняются из корня распакованного комплекта. Для первого получения Python/npm-пакетов нужна сеть; расчёт и сборка материалов после установки работают локально.

Windows PowerShell:

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe -m pip check
.venv/Scripts/python.exe -X utf8 -B scripts/verify_delivery.py
.venv/Scripts/python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

Linux/macOS:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pip check
.venv/bin/python -X utf8 -B scripts/verify_delivery.py
.venv/bin/python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

Откройте http://127.0.0.1:8000. Остановка — Ctrl+C. Готовый frontend/dist включён, поэтому Node не нужен для обычного запуска. Далее `python` в командах означает Python созданного окружения; в PowerShell используйте `.venv/Scripts/python.exe`.

Пересборка интерфейса из закреплённого lockfile:

```sh
npm --prefix frontend ci
npm --prefix frontend run build
```

Проверка KIT_MANIFEST относится к исходному поставляемому комплекту и выполняется до намеренных правок/пересборок. После собственных изменений создайте новый комплект и новый manifest; не подменяйте старые контрольные хеши.

## Один контейнер

Из корня **готового комплекта**, где расположен Dockerfile:

```sh
docker build -t kosmos:local .
docker run --rm --name kosmos-local -p 127.0.0.1:8000:8000 kosmos:local
```

Откройте http://127.0.0.1:8000. Остановка в другом терминале: `docker stop kosmos-local`. Сборка использует закреплённые digest базовых образов, npm ci и точные Python-зависимости. Один конечный контейнер запускает FastAPI и готовый интерфейс. Работа приложения не требует внешних API, CDN, LLM, токенов или личных файлов. Контейнер запускается от непривилегированного пользователя.

Не выполняйте Docker build из исходной рабочей папки с историческими отчётами. Сначала сформируйте безопасный комплект:

```sh
python -X utf8 -B scripts/build_delivery.py --output delivery/gitverse
```

Назначение и ZIP должны быть новыми. Сборщик выбирает разрешённые деревья и только активные выпуски по двум pointer manifests, проверяет их хеши; исторические генерации не перечисляет. Результат — папка и ZIP рядом с ней. Затем перейдите в delivery/gitverse и используйте Docker-команды выше. В распакованном комплекте повторная упаковка также доступна.

## Пересчёт и документы

Сохранённая рекомендация: config/m3_decision.json; управленческие условия: config/management.json и config/assumptions.json. Новые расчёты сохраняйте в новые пути:

```sh
python -c "from pathlib import Path; Path('out').mkdir(exist_ok=True)"
python -X utf8 -B scripts/reproduce.py config/m3_decision.json --decision --output out/decision.json
python -X utf8 -B scripts/build_management.py --output-dir out/m4
python -X utf8 -B scripts/build_submission.py --output-dir out/m5
python -X utf8 -B scripts/build_submission.py --current --output-dir out/m5
```

Результаты первых двух команд — аналитический JSON и полный управленческий JSON/CSV/Markdown. PDF-генератор заново считает ту же конфигурацию и создаёт записку 8–12 страниц, отдельное стресс-резюме 1 страницу, презентацию до12слайдов, редактируемые content.json/md, protocols.md, таблицы CSV, bundle и идентификаторы. Он печатает фактические пути. Все таблицы/графики/PDF одного выпуска происходят из одного bundle. Собственные рыночные цены, договоры и достигнутые KPI не заявлены.

`results/m4_current.json` и `results/m5_current.json` указывают на поставленные действующие материалы. `scripts/build_submission.py --current` проверяет и показывает их. Команда без --output-dir создаёт новый активный выпуск в текущем проекте; для проверки используйте отдельное назначение. Полные статьи организаторов не нужны для пересборки; тезисы, страницы и ограничения указаны в docs/sources.md.

## Проверки

Переносимая независимая проверка, созданная Tester на M3 и сохранённая отдельно от production:

```sh
python -X utf8 -B tests/m3_independent.py --output out/independent
```

Она независимо проверяет арифметику всех24пар и5670портфелей, контрольные варианты, условия, ранжирование, sensitivity, API/CLI и неизменность источников. Это не отсутствовавший оригинальный verify_case.py организаторов. Выходная папка должна быть новой. Итог PASS и exit0 обязательны.

Проверка фактических действий браузера Main по позднему указанию работать без субагентов на M6/M7; требуются npm ci и установленный Chrome:

```sh
python -X utf8 -B tests/m3_browser_run.py --oracle results/m3_decision.json --browser-script tests/m6_browser.mjs --output out/browser
```

Скрипт сам запускает и закрывает свой локальный сервер/браузер, сохраняет screenshots, downloads, console и результат. KOSMOS_BROWSER_CHANNEL позволяет выбрать другой установленный канал, например msedge. Специальное скачивание Chromium не требуется. Браузерный пакет — dev dependency, не часть обязательного runtime.

## Демонстрация

1. «Обзор» → «Открыть сохранённое решение и PDF» → загрузить сохранённый состав в конструктор.
2. Проверить состав, C0/OPEX/CASH/VPUB и девять ограничений. Изменить лот или режим — получен новый серверный расчёт.
3. «Стресс-сценарий»: одинаковая стоимость при разных лимитах BASE/STRESS. FAIL не скрывает причины.
4. Добавить два разных варианта в сравнение; открыть поиск и загрузить альтернативную стратегию.
5. Скачать/импортировать JSON, отменить изменение, перезагрузить страницу. При ошибке импорта настройки сохраняются, числа скрыты до успешного пересчёта.
6. Скачать три PDF в «Реализация и материалы». Они явно относятся к сохранённому выпуску, а не автоматически к ручному варианту.
