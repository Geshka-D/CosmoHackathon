# Session 2 · live decision experience

Audience: jury on a laptop. Job: understand why a feasible portfolio deserves a
conditional management decision, then challenge its budget and required services.

Continue the existing engineering atlas: sheet #ece8e1, field #f8f6f2, graphite
#1b2126, decision teal #0f5468, research ochre #8a5510, failure #8f3227. Bahnschrift
display, Segoe UI body, Consolas numbers. All local; no network font or new library.

Signature: the decision corridor, narrowing an already computed population into
a shortlist and recommendation. Its replay is explicitly an explanation of known
results. The official budget line moves while portfolio cost remains stationary.
Research uses a separate labelled surface and exact engine transition intervals.

Layout: overview → why/alternatives → official shock → research/recovery → funding
chain → conditions → deterministic brief. Existing manual workspace remains a
supporting tool. Pitch changes visibility of the mounted components; never copies
results into separate slides or owns an engine. Back/Next/Reset affect presentation
only; exit restores the normal product. Research and locks have their own reset.

Motion: occasional state indication, CSS transform/opacity, 240ms strong ease-out;
pipeline replay is explanatory, staggered by 60ms. No fake progress, spatial data,
moving chart points, or decoration masquerading as computation. Reduced motion
and keyboard access are required. Reuse the existing matrix and APIs.

Verification is single-session author validation, no independent-role acceptance.
No Polza experiment planned: deterministic demo reliability takes priority.
